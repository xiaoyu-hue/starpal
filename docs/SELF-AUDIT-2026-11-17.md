#### H1【高·真漏洞】所有限流可被绕过——限流键含客户端可控的 User-Agent ✅ 已修复（批次1）

> 修复（2026-11-18）：`subject.ts` 限流摘要去掉 UA，只用可信 IP（Vercel 覆盖 XFF 的首值）；
> 新增 `auth-failure-limit.test.ts` 7 项含"换 UA 不绕过"回归 + 变异验证；后端 317→324，verify 全绿。
- **位置**：`server/src/modules/auth/subject.ts:16-27`
- **大白话**：限流靠给每个请求算一个"来源编号"来计数。但这个编号是用 `IP + User-Agent` 算出来的，
  而 User-Agent（浏览器标识）是**请求方自己随便填的**。攻击者每发一次请求就换一个假 UA，
  就得到一个全新的"来源编号"，于是每一次都被当成新的人，计数永远从 0 开始。
- **影响面**（都复用同一个 `subjectHashOf`）：
  - 登录失败限次（口令爆破的"5 次锁定"形同虚设）— `auth.service.ts:112`
  - 注册限流、ALTCHA 挑战生成限流 — `auth.controller.ts:34`
  - 四类写接口限流（刷帖 / 刷评论 / 刷举报 / 刷上传）— `write-rate-limit.ts:25-27`
- **补充**：`subject.ts:18` 取的是 `x-forwarded-for` 的**首值**。若平台是"追加"真实 IP 而非覆盖，
  首值就是攻击者伪造的值（需按 Vercel 实际行为核实）。登录前仍需解一次 ALTCHA（cost=10000）
  是唯一残存屏障，但挡不住刷写接口。
- **修复建议**：限流键**去掉 User-Agent**；XFF 仅在确认可信代理覆盖的前提下采信，且取最右侧可信值；
  登录改为"账号 + IP"双维度计数；写接口保持 PoW/认证之外的独立配额；补一条"换 UA 不能绕过限流"的测试。
